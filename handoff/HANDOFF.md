# تحویل کار: بازنویسی شرح نهج‌البلاغه و غررالحکم (مشکات)

آخرین به‌روزرسانی: ۱۹ آبان ۱۴۰۵ (2026-11-10) — شاخهٔ `claude/sleepy-tesla-jm2ik6`

## هدف
مالک پروژه می‌خواهد ترجمه‌ها و شرح‌ها **کتابی و نامفهوم نباشند** و عمق حکمت‌ها را برسانند.
فعلاً فقط دو کتاب: **نهج‌البلاغه** (`books/Nahj-al-Balagha-Radi.json`) و **غررالحکم** (`books/ghurar.json`).

## معیار نگارش (تأییدشده توسط مالک)
| فیلد JSON | برچسب در اپ | محتوا |
|---|---|---|
| `fa` | ترجمه | فارسی روان امروزی، وفادار به عربی. در نهج‌البلاغه «امام فرمود:» حفظ می‌شود |
| `sm` | «یعنی چه؟» | **مقصود خود امام**: فقط معنای سخن بر پایهٔ واژه‌ها و زمینه؛ بی‌مثال امروزی، بی‌برداشت شخصی |
| `w` | «واژه‌های کلیدی» | `[[واژهٔ عربی, معنی دقیق]]` برای ۱ تا ۴ واژهٔ مهم |
| `dp` | «عمیق‌تر» | **برداشت امروزی**: منطق حکمت + ۲–۳ مثال واقعی امروز + مرز (چه چیزی را نمی‌گوید). پاراگراف‌ها با `\n`. حدود ۵۰۰–۹۰۰ نویسه |
| `mr` | پرسش تأمل | مشخص و مخصوص همان حدیث؛ قالب تکراری «آیا در زندگی‌ات…؟» ممنوع |
| `tg` | موضوعات | ۱ تا ۳ شناسه **فقط** از فهرست ۴۵ موضوع زیر |
| `nt` | توضیح | فقط وقتی `dp` نباشد نمایش داده می‌شود؛ دست نزنید |

قواعد محتوایی: آیه یا حدیث فقط با نشانی دقیق و مطمئن نقل شود؛ برداشتی که متن پشتش نیست ننویسید؛ تفسیر مورد اختلاف را قطعی نکنید؛ نیم‌فاصله (ZWNJ) درست باشد («استفاده‌یِ» غلط است).

نمونهٔ مرجع کیفیت: حکمت ۱ نهج‌البلاغه و ۲۰ موردِ `handoff/samples-batch-01.json` (حکمت‌های ۲۱–۲۹ و ده حدیث اول غرر).

## وضعیت فعلی
نهج‌البلاغه (۲٬۲۶۰ بند):
- خطبه‌ها: شرح تا حدود خطبهٔ ۱۹۷ هست؛ **۴۴ خطبه از ۱۹۸ به بعد** شرح ندارند.
- نامه‌ها (۷۹ نامه، ۴۵۰ بند): **هیچ شرحی ندارند.**
- حکمت‌ها (۶۱۹): فقط حکمت‌های ۱–۲۹ شرح دارند (فصل اول و ۱۰ بند اول فصل دوم). **ادامه از بند `i=33` (حکمت ۳۰).**

غررالحکم (۱۱٬۱۹۲ حدیث):
- همه `sm`/`dp` دارند ولی **سطحی‌اند** (میانهٔ `dp` ۱۴۰ نویسه) و باید با معیار بالا بازنویسی شوند.
- **شرح‌های جابه‌جا:** دست‌کم ۹۴ حدیث شرحِ حدیث دیگری را دارند (مثلاً «ذهاب البصر…» شرحِ «سخن‌چینی» داشت). علت احتمالی: ۱۱ مقدار تکراری `i`؛ تطبیق را با جایگاه (بخش/فصل/ترتیب) انجام دهید نه با `i`.
- ده حدیث اول بازنویسی شده‌اند؛ **ادامه از بخش ۰، فصل ۰، حدیث یازدهم.**

`books/topics.json`:
- ۱۲۲ کلید دارد ولی اپ فقط ۴۵ موضوع بالا را می‌شناسد؛ ~۸۰ کلید زائد/تکراری (مثل `ilm`، «علم»، «علم و دانا»). بعد از بازنویسی باید از روی `tg` دوباره ساخته شود.
- ساختار هر مدخل: `[bookId, sectionIdx, chapterIdx, i, fa, sm]`.

## روش اعمال
`handoff/apply.py <batch.json>`: موارد را در JSONها به‌روز می‌کند، مدخل‌های topics همان موارد را بازسازی می‌کند و نام کش `sw.js` را عوض می‌کند (بدون این، گوشی کاربران نسخهٔ قدیمی کتاب را از کش نشان می‌دهد). ساختار batch مثل `samples-batch-01.json`: `nahj` با کلید `i`، و `ghurar` فعلاً به‌ترتیب ده حدیث اولِ فصل اول — برای دسته‌های بعدی باید اسکریپت را به آدرس‌دهی `[section, chapter, index]` تغییر داد.

فایل‌ها یک‌خطی (minified) با `ensure_ascii=False` ذخیره می‌شوند.

## هشدار مهم
این مخزن **خروجی build** است (`sw.js` می‌گوید با `scripts/make-sw.mjs` ساخته شده). اگر کد منبع و دادهٔ خام جای دیگری است، تغییرات باید **آنجا** اعمال شوند وگرنه build بعدی پاکشان می‌کند. اول این را روشن کنید.

## ایدهٔ بعدی: «بپرس» با هوش مصنوعی (هنوز شروع نشده)
- دکمهٔ «بیشتر توضیح بده» و «بپرس» زیر هر حدیث؛ متن عربی + fa + sm + dp همان حدیث به‌عنوان زمینه فرستاده شود.
- سرور واسط (مثلاً Cloudflare Worker) برای پنهان ماندن کلید API و سقف روزانه برای هر کاربر.
- مدل پیشنهادی Claude Opus 5.5 (حدود ۰٫۰۲۵ دلار برای هر سؤال؛ گزینهٔ ارزان‌تر Sonnet 5.5 / Haiku 5.5).
- قواعد: جعل نکردن حدیث، جدا کردن «مقصود امام» از «برداشت»، فتوا ندادن و ارجاع به مرجع، گفتن «نمی‌دانم»، برچسب «پاسخ هوش مصنوعی».
- مانع باز: مالک باید بررسی کند در ایران امکان قانونی داشتن حساب API را دارد یا نه.

## کارهای بعدی به ترتیب
1. گرفتن نظر مالک دربارهٔ ۲۰ نمونه (هنوز نظر نداده).
2. روشن کردن جای کد منبع.
3. حکمت‌های نهج‌البلاغه از حکمت ۳۰ → نامه‌ها → خطبه‌های ۱۹۸ به بعد.
4. بازنویسی غررالحکم (با رفع شرح‌های جابه‌جا).
5. پاک‌سازی `topics.json`.
6. پس از هر دسته: commit و push، و ادغام در `main` فقط با اجازهٔ مالک.
